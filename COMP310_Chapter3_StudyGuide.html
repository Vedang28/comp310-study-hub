Symbolic Reasoning Agents
Slides 5-7 | 0:55
Core Definition

A deliberative agent is one that contains an explicitly represented, symbolic model of the world and makes decisions via symbolic reasoning. This paradigm is known as symbolic AI.

Two Fundamental Problems

T
The Transduction Problem
Translating the real world into accurate symbolic descriptions in time for them to be useful. "Identifying objects is hard!!!" Led to research in vision, speech, and learning.
R
The Representation/Reasoning Problem
How to symbolically represent complex real-world entities and reason with them in time. Symbol manipulation algorithms are highly intractable and hard to find compact representations for.
Important

Most researchers accept that neither problem is anywhere near solved. This is why alternative techniques (reactive, hybrid) were developed.

Deductive Reasoning Agents
Slides 8-10 | 2:02
Key Idea

In logical-based approaches, decision-making is viewed as deduction. The agent's strategy is encoded as a logical theory, and selecting an action reduces to a problem of proof.

Agent Anatomy: Two Components

Δ
Logical Database (Delta)
The agent's working memory. A set of first-order predicate logic formulae describing the agent's current internal state.

Examples:
Open(valve221)
Temperature(reactor4726, 321)
Pressure(tank776, 28)
ρ
Deduction Rules (Rho)
The agent's instincts / theory. A set of deduction rules of the form:

ψ(...) → φ(...)

Example:
In(0,0) ∧ Facing(north) ∧ ¬Dirt(0,0) → Do(forward)

Perception & Next State Functions

  • The perception function: see : E → Per maps environment states to percepts (much easier said than done!)
  • The next state function revises the database: next : Δ × Per → Δ
  • The action function is defined in terms of deduction rules
  • Δ ⊢ρ φ means that φ can be proved from Δ using ρ
Exam Tip

Remember the analogy: Δ is like your memory (where the ball was), and ρ is like your instincts (how to reach out). Combined, they mathematically deduce the correct action.

The Action Function
Slide 11 | 3:01

Pseudocode: How the Agent Chooses an Action

/* Loop 1: Try to find an action explicitly prescribed */
for each α ∈ Ac do
    if Δ ⊢ρ Do(α) then
        return α
    end-if
end-for

/* Loop 2: Try to find an action not excluded */
for each α ∈ Ac do
    if Δ ⊬ρ ¬Do(α) then
        return α
    end-if
end-for

return null     /* no action found */

How It Works (Step by Step)

  1. Loop 1 — Explicit match: Scans every possible action asking "Can I prove I must do this?" If yes, execute immediately.
  2. Loop 2 — Fallback: If no action is explicitly prescribed, find any action that is at least not excluded by the rules (not provably wrong).
  3. Null — Freeze: If even the fallback fails, return null. The agent freezes — no action found.

Deduction Rule Structure

ψ (conditions / facts about the world) ⟶ φ (action to take)

When conditions on the left are met in Δ, the agent deduces and executes the action on the right.

Exam Tip

The two loops represent two levels of reasoning: (1) provably correct actions first, then (2) not provably wrong actions as fallback. This distinction is important!

Transcript (3:01 - 4:30)
Walk through this step by step. The action function first runs through a loop, scanning every single possible action it could take. It's asking itself, can I prove using my current memory and rules that I absolutely must do this specific action? If it finds an explicitly prescribed action, it executes it immediately. But you know, the real world is totally unpredictable and developers simply can't program a specific rule for every single scenario. That's exactly why the second loop acts as a fallback. It searches for any action that is at least not excluded by its rules. Basically, it tries to find something, really anything, that isn't explicitly a bad idea. If even that fails, it returns null, which means no action is found and the agent just freezes. Now that we understand how the action function searches for an answer, how do we write the actual rules it's searching for? Well, here is the basic and frankly elegant structure of a deduction rule. Over on the left side, we have psi, which represents a specific condition or a set of facts about the world. On the right side, we have phi, representing the action to take. That arrow in the middle simply means implies.

Limitations of Logical Agents
Slides 15-16 | 7:24

Three Critical Flaws

#ProblemExplanation
1 Transduction Problem Incredibly difficult to convert complex sensory input (camera feed) into clean logical symbols like Dirt(0,1). A perfect brain fed bad data is useless.
2 Calculative Rationality The agent assumes the environment stays perfectly static while it calculates proofs. In the real world, things move.
3 Undecidability Decision-making using first-order logic is undecidable — no guarantee the system will always find a solution in finite time.

Typical Solutions

  • Weaken the logic — use simpler, decidable fragments
  • Use symbolic, non-logical representations — alternative formalisms
  • Shift reasoning from run time to design time — pre-compute decisions
  • Move beyond deduction into probabilistic reasoning, machine learning, and neural networks
Critical Understanding

The vacuum world works perfectly in a clean, predictable 3×3 grid. But real engineering is messy. A real vacuum robot must process chaotic, blurry video and translate raw pixels into crisp mathematical symbols — if this translation is flawed, all subsequent logic leads to completely wrong actions.

Agent-Oriented Programming
Slides 18-23
Definition

Yoav Shoham (1990) introduced agent-oriented programming — "a new programming paradigm, based on a societal view of computation." The key idea: program agents directly in terms of intentional notions (beliefs, desires, intentions).

AGENT0 Language

Implemented as an extension to LISP. Each agent has 4 components:

  1. A set of capabilities (things the agent can do)
  2. A set of initial beliefs
  3. A set of initial commitments (things the agent will do)
  4. A set of commitment rules

A program = initialisation + commitment rules.

AGENT0 Decision Cycle

A commitment rule fires when:

  • The message condition matches received messages
  • The mental condition matches the agent's beliefs
  • If both match → agent becomes committed to the action

Actions can be:

  • Private — internally executed computation
  • Communicative — sending messages

Messages are one of three types:

  • Requests — commit to actions
  • Unrequests — refrain from actions
  • Informs — pass on information

Commitment Rule Example

COMMIT(
  ( agent, REQUEST, DO(time, action) ), ;;; msg condition
  ( B,
    [now, Friend agent] AND
    CAN(self, action) AND
    NOT [time, CMT(self, anyaction)]
  ), ;;; mental condition
  self,
  DO(time, action)
)

In English: If a friend requests me to do an action, and I can do it, and I'm not already committed to something else at that time → then commit to doing it.

PLACA (Planning Communicating Agents)

  • Developed by Sarah Rebecca Thomas (1993 doctoral thesis)
  • Addresses AGENT0's inability to plan and communicate requests via high-level goals
  • Agent mental states expanded to include plans and intentions
  • Uses mental-change rules instead of just commitment rules
