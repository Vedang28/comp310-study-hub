What is Practical Reasoning?
Slides 3-4 | 0:00
Core Definition

Practical reasoning is reasoning directed towards actions — the process of figuring out what to do. It is distinct from theoretical reasoning, which is directed towards beliefs.

"Practical reasoning is a matter of weighing conflicting considerations for and against competing options, where the relevant considerations are provided by what the agent desires/values/cares about and what the agent believes..."
— Bratman

Two Components of Practical Reasoning

D
Deliberation
Deciding what state of affairs to achieve. The outputs are intentions.
M
Means-Ends Reasoning
Deciding how to achieve those states. The outputs are plans.

The interplay between beliefs, desires, and intentions defines how the BDI model works.

Intentions in Practical Reasoning
Slides 5-9 | 0:54

7 Properties of Intentions

#PropertyMeaning
1Intentions pose problemsAgents must determine ways of achieving them — devote resources to deciding how to bring about φ
2Intentions filterNew intentions must not conflict with existing ones
3Agents track successIf first attempt fails, try an alternative plan
4Believed possibleAgents believe there is at least some way to achieve them
5No belief of failureWould not be rational to adopt φ if you believed you'd fail
6Believed achievableUnder "normal circumstances" agents believe they will succeed
7Side-effect problemIntentions are NOT closed under implication (the package deal problem)
Exam Tip - Side Effect Problem

"I may believe going to the dentist involves pain, and I intend to go to the dentist — but this does NOT imply I intend to suffer pain!" If I believe φ ⇒ ψ and I intend φ, I do not necessarily intend ψ.

"My desire to play basketball this afternoon is merely a potential influencer of my conduct. It must vie with my other relevant desires before it is settled what I will do. In contrast, once I intend to play basketball this afternoon, the matter is settled: I normally need not continue to weigh the pros and cons."
— Michael E. Bratman (1990)
Key Distinction

Intentions are stronger than desires. A desire competes with other desires; an intention is a settled commitment to action.

Means-Ends Reasoning & STRIPS
Slides 10-13 | 2:17

Planning = Automatic Programming

Give a planning system three inputs and it generates a plan:

  1. Representation of the goal/intention to achieve
  2. Representation of the actions it can perform
  3. Representation of the environment

The planner outputs a plan to achieve the goal. You don't tell it what to do — it figures it out!

STRIPS Planner

Stanford Research Institute Problem Solver — developed by Richard Fikes and Nils Nilsson in 1971. Used by Shakey, the robot.

  • World model as first-order logic formulae
  • Actions described by action schemata (preconditions + effects)

Three Parts of Every STRIPS Action

Preconditions
Facts that must be true for the action to be attempted
Delete List
Facts that are no longer true after the action
Add List
New facts that become true after the action

Search Strategies

Forward Search
Start from current state, progress forward through actions toward goal
Backward Search (Goal Regression)
Start from desired goal, work backwards to find required starting conditions
Transcript (2:17 - 3:51)
Which brings us right to section 2, automated planning and strips, the architecture of action. Think of strips, which stands for Stanford Research Institute Problem Solver, as the strict mathematical grammar an agent uses to understand cause and effect. It breaks down literally every possible action into three absolute rules. First, preconditions — things that must be true right now. Second, the delete list — facts that will no longer be true. Third, the add list — brand new facts that become true. An agent can use forward search or backward search (goal regression) to find a valid path from initial state to goal.

STRIPS Action Schemas
Slides 16-18, 26 | 4:54

The Four Blocksworld Actions

Stack(x, y)
Place held block x on top of block y
pre Clear(y) ∧ Holding(x)
del Clear(y) ∧ Holding(x)
add ArmEmpty ∧ On(x,y)
Pickup(x)
Pick up block x from the table
pre Clear(x) ∧ OnTable(x) ∧ ArmEmpty
del OnTable(x) ∧ ArmEmpty
add Holding(x)
UnStack(x, y)
Pick up block x from on top of block y
pre On(x,y) ∧ Clear(x) ∧ ArmEmpty
del On(x,y) ∧ ArmEmpty
add Holding(x) ∧ Clear(y)
PutDown(x)
Place held block x onto the table
pre Holding(x)
del Holding(x)
add OnTable(x) ∧ ArmEmpty ∧ Clear(x)
Action Definitions are Important!!!

A single missing precondition (e.g., forgetting Clear(x) in UnStack) will completely break the agent. It might try to unstack a block from the middle of a tower — all because the logic wasn't watertight. This appeared in the mock paper!

Transcript (4:54 - 7:01)
To execute a stack action, the agent checks preconditions: block Y must be clear and the agent must be holding X. If both are true, the action fires. It deletes old states and adds new ones. Conversely, unstacking requires inverted logic. The agent must verify X is on Y, X is clear, and the arm is empty. A single missing precondition will completely break the agent's ability to interact with the environment. By clearly defining initial beliefs and goal intentions, the agent uses strip sequences to bridge the gap, calculating the shortest sequence of actions.

Formal Plan Representation
Slides 20-22

Planning Problem Definition

Planning Problem = < B0, Ac, I >
  • B0 = initial set of beliefs about the world
  • Ac = set of available actions
  • I = goal (intention)

Action Structure

Each action αi has structure:

αi = < Pαi , Dαi , Aαi >

A plan π = (α1, ..., αn) — a sequence of actions from Ac.

Plan Validity

  • A plan is acceptable if: for all 1 ≤ j ≤ n, Bj-1 ⊨ Pαj (preconditions met at each step)
  • A plan is correct if: it is acceptable AND Bn ⊨ I (final state satisfies the goal)
  • Beliefs update at each step: B0 ⟶α1 B1 ⟶α2 ... ⟶αn Bn
Exam Tip

At each step, beliefs are updated by removing delete list items and adding add list items. Preconditions don't need to literally be in Bj-1, they just need to be provable from Bj-1.

Agent Control Loop Evolution
Slides 27-33 | 0:54

Version 1: Simple Loop

while true do
  observe the world;
  update internal world model;
  deliberate about what intention to achieve next;
  use means-ends reasoning to get a plan;
  execute the plan
end while

Version 2: Formal BDI Loop V2

1. B := B0; /* initial beliefs */
2. while true do
3.   get next percept ρ;
4.   B := brf(B, ρ);
5.   I := deliberate(B);
6.   π := plan(B, I);
7.   execute(π)
8. end while

Version 3: With Option Generation & Filtering V3

1. B := B0;   I := I0;
2. while true do
3.   get next percept ρ;
4.   B := brf(B, ρ);
5.   D := options(B, I); /* generate desires */
6.   I := filter(B, D, I); /* select intentions */
7.   π := plan(B, I, Ac);
8.   execute(π)
9. end while

Key Functions

FunctionSignaturePurpose
seeE → PerPerception (environment to percepts)
brfP(Bel) × Per → P(Bel)Belief revision from percepts
optionsP(Bel) × P(Int) → P(Des)Generate desires from beliefs + intentions
filterP(Bel) × P(Des) × P(Int) → P(Int)Select intentions from desires
planP(Bel) × P(Int) × Ac → PlanGenerate action plan
The Time Cost Problem

Deliberation is not instantaneous. The world may change while the agent thinks. Even if it computes the optimal plan, by the time it finishes, the environment may have moved on. This is calculative rationality — optimality is hard.

Transcript (1:44 - 2:17)
But you know, there's a massive catch here. Deliberation is not instantaneous. Thinking has a real-time cost. Because the world might literally change while an agent is just sitting there thinking. Achieving pure, calculative rationality, where the agent perfectly executes the mathematically optimal intention, is incredibly difficult. By the time it finishes computing that perfect optimal plan, the environment might have already moved on.

Degrees of Commitment
Slides 34-42

The Willie the Robot Story

Under-commitment: "Willie, bring me a beer." "OK boss." 20 minutes later: "Why didn't you bring me that beer?" "Well, I intended to, but I decided to do something else."
Over-commitment: Willie is returned as "Model C: The Committed Assistant." You ask for a beer. It gets Genesee. You say "Never mind." One minute later, Willie trundles over with a Genesee in its gripper...
Wise Guy: You ask Willie to bring your last beer. It gets it, starts walking toward you, lifts its arm, wheels around, deliberately smashes the bottle, and trundles off. "The commitment became unachievable."

P. R. Cohen and H. J. Levesque (1990). Intention is choice with commitment.

Three Types of Commitment

TypeWhen to Drop IntentionRisk
Blind (Fanatical) Only when achieved Keeps pursuing impossible goals forever
Single-minded When achieved OR believed impossible May miss better alternatives
Open-minded As long as still believed possible Costly — constant reconsideration

Control Loop Version 4: Replan When Unsound V4

1. B := B0; I := I0;
2. while true do
3.   get percept; B := brf(B,ρ); D := options(B,I); I := filter(B,D,I);
4.   π := plan(B, I, Ac);
5.   while not empty(π) do
6.     α := hd(π); execute(α); π := tail(π);
7.     get percept; B := brf(B,ρ);
8.     if not sound(π, I, B) then π := plan(B, I, Ac);
9.   end-while
10. end-while

Not committed to means (replans), but still overcommitted to ends (never reconsiders intentions).

Version 5: Single-Minded Commitment V5

Inner loop condition changes to:

while not(empty(π) or succeeded(I,B) or impossible(I,B)) do

Agent exits when: plan done, intention achieved, or intention impossible.

Version 6: Open-Minded Commitment V6

Adds intention reconsideration after every action (lines 15-16):

  ...
  B := brf(B,ρ);
  D := options(B,I); I := filter(B,D,I); /* reconsider every step */
  if not sound(π, I, B) then π := plan(B, I, Ac);
  ...

Problem: constant reconsideration is expensive!

Exam Tip

Commitment to ends = the state of affairs the agent wants. Commitment to means = the specific plan. Version 4 drops means-commitment; Version 5 adds single-minded ends-commitment; Version 6 adds open-minded reconsideration.

Intention Reconsideration
Slides 43-45

The Reconsideration Dilemma

Never Reconsider
Agent keeps pursuing intentions even when clearly impossible or pointless
Always Reconsider
Agent spends so much time reconsidering that it never actually achieves anything

Version 7: Meta-Level Control V7

Solution: add a reconsider(I, B) function that decides whether to deliberate:

...
B := brf(B, ρ);
if reconsider(I, B) then
  D := options(B, I);
  I := filter(B, D, I);
end-if
if not sound(π, I, B) then π := plan(B, I, Ac);
...

When is reconsider() Optimal?

SituationDeliberate?Changed?Would have changed?Optimal?
1No—NoYes (saved time)
2No—YesNo (missed opportunity)
3YesNo—No (wasted time)
4YesYes—Yes (needed change)

Key assumption: cost of reconsider() is much less than the cost of full deliberation.

Exam Tip - The Closing Paradox

We can calculate mathematically optimal plans and expected utilities. But deliberation has a time cost. In a rapidly changing multi-agent world, the most rational thing an agent can do might be to learn when to stop thinking and start acting.

Transcript (9:19 - end)
But all of this leaves us with a totally profound paradox to close on. We just proved mathematically how to calculate the perfect sequence of actions and their expected utilities. But remember what we talked about at the very beginning? Deliberation has a time cost. If calculating this perfect, mathematically optimal plan in a rapidly changing, multi-agent real world takes too long, perhaps the most rational thing an agent can possibly do is learn exactly when to stop thinking and start acting.
