The Reactive AI Challenge
Slides 2–5 • 🎬 0:28

Why Deliberation Fails in Dynamic Worlds

Traditional symbolic/deliberative agents suffer from a fundamental bottleneck: thinking takes time. While an agent computes the perfect plan, the environment may have already changed — making the plan obsolete.

  • Calculative rationality assumes the world stays still during computation — rarely true in practice
  • Decision-making using first-order logic is undecidable in general
  • The transduction problem: converting raw sensor data into clean logical symbols is extremely hard

Reactivity Defined

A reactive system maintains an ongoing interaction with its environment and responds to changes that occur in it fast enough for the response to be useful. No internal world model, no complex reasoning — just immediate stimulus → response.

Problems with Symbolic AI (Recap)

  • Transduction problem — translating real-world sensor data into accurate symbolic representations
  • Representation/reasoning problem — symbolically representing complex, dynamic environments and reasoning with that information in time to act
  • Symbolic AI has not delivered on the promise of general-purpose intelligent control for real-world agents

A common exam question asks you to explain why purely deliberative agents struggle in dynamic environments. Hit these three points: (1) calculative rationality assumption, (2) transduction problem, (3) undecidability of first-order logic.

Brooks' Three Theses
Slides 6–9 • 🎬 1:12

Rodney Brooks' Radical Propositions

Brooks argued that intelligent behaviour could arise without explicit symbolic representations or abstract reasoning. His three key theses:

Thesis 1: Intelligent behaviour can be generated without explicit representations

No need for symbolic knowledge representation. Behaviour emerges from the agent's direct coupling with the environment — no world model required.

Thesis 2: Intelligent behaviour can be generated without explicit abstract reasoning

Planning and logical deduction are unnecessary for producing intelligent-looking behaviour. Simple situation-action rules suffice.

Thesis 3: Intelligence is an emergent property of complex systems

Complex behaviour need not be explicitly programmed — it emerges from the interaction of simpler components with the environment and each other.

Brooks' three theses are frequently tested. Memorise them and be ready to both explain each thesis and critique it (e.g., thesis 3 makes validation nearly impossible since emergent behaviour is hard to predict).

Subsumption Architecture
Slides 10–13 • 🎬 1:50

How Subsumption Works

The subsumption architecture organises behaviours into a strict hierarchy of layers. Each layer is an independent behaviour module that maps sensor input directly to actuator output.

  • Lower layers = more primitive, higher priority (e.g., obstacle avoidance)
  • Higher layers = more abstract, lower priority (e.g., exploration)
  • Lower layers can inhibit (subsume) the outputs of higher layers
  • Each layer is independently testable
┌─────────────────────────────────┐ │ Layer n (explore) │ ← lowest priority ├─────────────────────────────────┤ │ ... │ ├─────────────────────────────────┤ │ Layer 2 (wander) │ ├─────────────────────────────────┤ │ Layer 1 (avoid obstacles) │ ← highest priority └─────────────────────────────────┘ ↑ sensors ↓ actuators Lower layers SUBSUME (override) higher layers

Key Design Principles

  • No central world model — each behaviour reads sensors directly
  • Parallel execution — all layers run simultaneously
  • Priority via inhibition — lower layers suppress higher layer outputs when active
  • Incremental construction — build and test layer by layer

Genghis: Brooks' Six-Legged Robot

Genghis demonstrated remarkably complex walking and navigation using subsumption — no world model, no planning. It could traverse rough terrain, follow humans, and avoid obstacles using just layered reflexive behaviours. This was considered groundbreaking evidence for Brooks' theses.

The beauty of subsumption is its modularity: each layer can be coded, tested, and debugged independently, then "snapped together" — complexity emerges from simplicity.

Mars Explorer / Foraging Robot
Slides 14–17 • 🎬 2:24

Steels' Mars Explorer Scenario

A classic exam scenario: design an autonomous robot to explore a planet, collect rock samples, and return them to a base station — using only subsumption (no central planner).

1
Avoid obstacles
If obstacle detected → change direction
2
Drop sample
If carrying sample AND at base → drop it
3
Return home
If carrying sample AND not at base → follow gradient to base
4
Pick up sample
If sample detected → pick it up
5
Wander
Default: move randomly to explore

Ant-Inspired Cooperation

When multiple robots are deployed, Steels added ant-like pheromone trails: robots drop "crumbs" when carrying samples. Other robots follow these crumb gradients to find sample-rich areas. This creates cooperative foraging without explicit communication — a classic example of stigmergy (indirect coordination through environment modification).

Be ready to list these 5 behaviours in the correct priority order (1 = highest) and explain why obstacle avoidance must be highest (safety/survival is non-negotiable). Also know the ant-cooperation extension.

Emergence & Flocking
Slides 18–20 • 🎬 3:42

What Is Emergence?

Emergence occurs when the observed behaviour of a system exceeds the coded behaviour — complex patterns arise from simple rules interacting with each other and the environment.

Coded Behaviour
The explicit rules programmed into each individual agent. What exists in the code.
Observed Behaviour
The collective pattern seen by an external observer. "In the eye of the beholder."

Emergence = Observed > Coded

When observed behaviour exceeds coded behaviour, we have emergence. There is no one-to-one mapping between the simple code and the complex reality that plays out — the interactions link the rules in ways we cannot fully anticipate.

Flocking: Reynolds' Boids & Mataric's Nerd Herd

Three simple rules produce complex, perfectly synchronised group movement:

#RulePurpose
1Separation — don't run into other robotsCollision avoidance
2Cohesion — don't get too far from othersGroup unity
3Alignment — keep moving if you canForward progress

When run in parallel across many agents, realistic flocking emerges naturally — no central coordinator needed.

The magic of emergence: three trivial rules → complex flocking. This demonstrates Brooks' Thesis 3 — intelligence as an emergent property of interacting simple systems.

Limits of Reactive Systems
Slides 18–20 • 🎬 5:14

Reactive agents have fundamental limitations that prevent them from being a complete solution to the agent design problem.

Four Critical Limitations

  1. No world model → short-term view only
    Agents rely purely on local, current sensor information. They cannot reason about the past or plan for the future.
  2. Sufficient local information required
    If the agent cannot perceive enough of the environment to determine the correct action, it will fail. The right action must be determinable from current percepts alone.
  3. Emergent behaviour is hard to engineer
    You cannot predict or guarantee what behaviour will emerge. Validation requires extensive trial and error — not formal verification.
  4. Scalability problem
    A few layers work well; many layers create an inherently complex, untestable system. The interactions between layers become unpredictable.

These limitations are the key motivation for hybrid architectures. An exam question may ask: "Why are purely reactive agents insufficient? How do hybrid architectures address this?" Connect each limitation to how deliberation/planning compensates for it.

Hybrid Architectures
Slides 21–23 • 🎬 5:58

The Hybrid Motivation

Neither purely deliberative nor purely reactive agents are sufficient. Hybrid systems marry both approaches:

  • A deliberative subsystem with a symbolic world model for planning
  • A reactive subsystem for fast, reflex-based responses
  • The reactive component typically gets precedence over the deliberative one

Layered Architecture

Hybrid agents naturally organise into a hierarchy of interacting layers, with higher layers dealing with information at increasing levels of abstraction. The key design problem: what control framework manages the interactions between layers?

Two Layering Strategies

Know the difference between horizontal and vertical layering. Horizontal = all layers see everything (like TouringMachines). Vertical = sequential pass through layers (like InteRRaP's two-pass model). Be able to draw both diagrams.

Ferguson's TouringMachines
Slides 24–27 • 🎬 7:08

Architecture Overview

TouringMachines is a horizontal layering hybrid architecture with:

  • Perception subsystem — interfaces with the environment (sensor input)
  • Action subsystem — interfaces with the environment (action output)
  • Three control layers embedded in a control framework that mediates between them
Reactive Layer
Situation-action rules (like Brooks' subsumption). Rules reference only the agent's current state — no explicit reasoning. Handles immediate reflexes.
Planning Layer
Achieves the agent's proactive behaviour. Responsible for "day-to-day" operation. Uses a library of plans (does NOT generate plans from scratch).
Modelling Layer
Contains symbolic representations of the cognitive state of other entities in the environment. Handles social reasoning about other agents.
Control Framework
Mediates between the three layers using control rules (censor rules). Can suppress/modify information flowing between layers.
sensor input ↓ ┌─────────────────┐ │ perceptual │ │ subsystem │ └────┬───┬───┬────┘ │ │ │ ┌─────↓─┐│┌──↓─────┐ │modelling│││reactive│ │ layer │││ layer │ └────┬──┘│└──┬─────┘ │ ┌─↓──┐│ │ │plan-││ │ │ning ││ │ │layer││ │ └──┬─┘│ ┌───↓────↓──↓──────┐ │ control subsystem│ ← mediates via └────────┬──────────┘ censor rules ↓ action output

Control Rules (Censor Rules)

The control framework uses censor rules to manage layer interactions. These can suppress sensory data from reaching certain layers:

rule-1: kerb-avoidance
    if
        is-in-front(Kerb, Observer) and
        speed(Observer) > 0 and
        separation(Kerb, Observer) < KerbThreshHold
    then
        change-orientation(KerbAvoidanceAngle)
censor-rule-1:
    if
        entity(obstacle-6) in perception-buffer
    then
        remove-sensory-record(layer-R, entity(obstacle-6))

The censor rule prevents the reactive layer from seeing obstacle-6, allowing the planning layer to handle it instead.

TouringMachines uses horizontal layering (all layers see sensor data) with a control framework to mediate. Know the three layers (reactive, planning, modelling) and how censor rules work. Common exam question: give an example of a censor rule and explain its purpose.

InteRRaP
Slides 28–29 • 🎬 (lecture only)

Architecture Overview

InteRRaP is a vertically layered, two-pass agent architecture. It contains three control layers, each with its own knowledge base:

Behaviour Layer
Reactive behaviours + world model (representation of the physical environment)
Plan Layer
Local planning + planning knowledge (plan library and planning strategies)
Cooperation Layer
Multi-agent coordination + social knowledge (models of other agents)
World Interface
Handles sensor input and action output — the agent's connection to its environment

Layer Interaction Mechanisms

MechanismDirectionDescription
Bottom-up activationLower → HigherA lower layer passes control to a higher layer because it cannot handle the current situation
Top-down executionHigher → LowerA higher layer uses the facilities provided by a lower layer to achieve its goals
┌──────────────┐ ┌──────────────┐ │ cooperation │←──→│ social │ │ layer │ │ knowledge │ ├──────────────┤ ├──────────────┤ │ plan │←──→│ planning │ │ layer │ │ knowledge │ ├──────────────┤ ├──────────────┤ │ behaviour │←──→│ world │ │ layer │ │ model │ ├──────────────┤ └──────────────┘ │ world │ │ interface │ └──────┬───────┘ ↗ ↘ sensor action input output ↑ bottom-up activation (can't handle → escalate) ↓ top-down execution (use lower layer's facilities)

InteRRaP vs TouringMachines is a likely comparison question. Key differences: InteRRaP = vertical two-pass, each layer has its own knowledge base. TouringMachines = horizontal, mediated by a central control framework with censor rules. Know both directions of interaction: bottom-up activation and top-down execution.
