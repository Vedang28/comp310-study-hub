1. Overview

How do agents reach agreements when they are self-interested? In an extreme case (zero-sum encounter) no agreement is possible — but in most scenarios, there is potential for mutually beneficial agreement on matters of common interest.

Two Key Capabilities

  • Negotiation — agents make concessions and explore tradeoffs (this chapter)
  • Argumentation — agents provide reasons and justifications (next chapter)

Mechanisms, Protocols & Strategies

  • Negotiation is governed by a mechanism (or protocol) — the "rules of encounter"
  • Mechanism design = designing mechanisms with desirable properties (e.g., Pareto efficiency)
  • Given a protocol, how can a particular strategy be designed for individual agents?

2. Auction vs. Negotiation

Auctions are only concerned with allocating goods. Negotiation is a richer process for reaching agreements on matters of common interest.

Four Components of Any Negotiation

  1. Negotiation set — the possible proposals agents can make
  2. Protocol — defines what legal proposals an agent can make, based on prior history
  3. Strategies — one per agent, typically private
  4. Rule — determines when a deal is struck and what the agreement is

Complexity Factors

  • Multiple issues — hard to compare offers across issues (the car salesman problem); exponential possible deals
  • Multiple agents — one-to-one / many-to-one / many-to-many

This chapter focuses on single-issue, symmetric, one-to-one negotiation settings.

3. Rubinstein's Alternating Offers

A classic one-to-one protocol where agents negotiate over a series of rounds:

Protocol Rules

0
Round 0: Agent 1 makes a proposal x0. Agent 2 either accepts (A) or rejects (R).
1
Round 1: If rejected, Agent 2 makes a proposal. Agent 1 accepts or rejects.
...
This continues, alternating proposers each round.

Key Limitation

The protocol does not guarantee agreement will be reached. Agents could keep rejecting forever. If there is no agreement, the result is the conflict deal, denoted Θ.

Two Fundamental Assumptions

  • Disagreement is the worst outcome — both agents prefer any agreement over the conflict deal
  • Agents seek to maximise utility — they prefer larger utility values
Show Transcript — Rubinstein's Protocol
This brilliantly illustrates Rubinstein's alternating offers protocol. It's a classic one-to-one setup that plays out over a series of rounds. In round zero, Agent 1 kicks things off by making a proposal. Agent 2 then has a super simple choice — accept it or reject it. But there's a pretty big catch here. The rules of this protocol alone don't actually guarantee that an agreement will ever be reached. These agents could theoretically just keep rejecting each other's proposals until the end of time.

4. Dividing the Pie

Model the negotiation as dividing a resource of value 1 into two parts. A proposal is a pair (x, 1−x) where 0 ≤ x ≤ 1.

Set of Possible Deals
{(x, 1 − x) : 0 ≤ x ≤ 1}

1 Round (Ultimatum Game)

  • Agent 1 has all the power
  • Agent 1 proposes (1, 0)
  • Agent 2 accepts — still better than the conflict deal
  • This is a Nash Equilibrium

2 Rounds

  • Power shifts to Agent 2
  • Whatever Agent 1 proposes, Agent 2 rejects
  • Then Agent 2 proposes (0, 1)
  • Agent 1 accepts — still better than conflict

With a Fixed Number of Rounds

The last proposer takes everything. This happens any time there is a fixed number of rounds. The other agent still accepts because any deal is better than the conflict deal.

5. Patient Players — Indefinite Rounds

What if there are an indefinite number of rounds?

Example Strategy for Agent 1

"Always propose (1, 0) and always reject any offer from Agent 2."

  • If Agent 2 continually rejects → conflict deal (worst outcome)
  • So Agent 2 should accept immediately — no point waiting

Infinite Nash Equilibria

Whatever (x, 1−x) Agent 1 proposes, immediate acceptance is the Nash equilibrium as long as Agent 2 knows Agent 1's strategy. There are thus infinitely many Nash Equilibria — and all are Pareto optimal.

The solution concept of Nash Equilibrium is too weak to help us here. We need something else...

6. Impatient Players & Discount Factors

We can get unique results by taking time into account. For any outcome x and times t2 > t1, both agents prefer x at time t1 over x at time t2. Agents are, to varying degrees, impatient.

Discount Factor δi

  • Each agent i has a discount factor δi where 0 ≤ δ < 1
  • The closer δi is to 1, the more patient the agent
  • The closer δi is to 0, the more impatient

Value Over Time

If agent i is offered x, the value of that slice over time is:

  • Time 0: x
  • Time 1: δi · x
  • Time 2: δi2 · x
  • Time k: δik · x
Intuition

The Hot Pizza Analogy

Imagine negotiating over a fresh, hot pizza. If you argue for an hour, by the time you agree, the pizza is cold — technically whole, but worth much less. That's exactly what discount factors model: delay erodes value.

Show Transcript — Discount Factors
Think about it like this. If a negotiation only has one round, it's essentially just an ultimatum game. But what happens in a two-round game, where time literally eats away at the value of the prize? Imagine negotiating over a fresh, hot pizza. If you sit there arguing for an hour, by the time you finally agree, the pizza is totally cold. A high delta, let's say 0.8, means the agent is highly patient. A low delta, like 0.2, means the agent is super impatient.

2-Round Game with Impatience

Key Insight: Patience = Power

The more patient either agent is (higher δ), the more pie they get. An impatient Agent 2 will accept a much smaller offer early because getting a tiny slice now is worth more than a delayed larger slice.

8. Negotiation Decision Functions

The strategic approach relies on thinking about the other player's discount factor. A simpler alternative: use a negotiation decision function — a time-dependent curve that shapes bargaining behaviour without considering the opponent at all.

Trade-off

Simplifies negotiation — no need to model the opponent. But fails to take the opponent's actions into account, so it can't exploit mistakes.

9. Boulware vs. Conceder

Two classic, totally opposite negotiation decision functions:

Boulware (Stubborn)

  • Very slow initial decrease in price
  • Holds firm for most of the negotiation
  • Then drops sharply near the deadline
  • Curve stays high, then falls steeply

Conceder (Yielding)

  • Makes concessions early
  • Price drops rapidly at the start
  • Makes fewer concessions later
  • Curve drops quickly, then flattens
Show Transcript — Boulware vs. Conceder
First, there's the stubborn Boulware function. This agent barely drops their asking price for the vast majority of the negotiation. They hold incredibly firm, making this very slow initial decrease until time is almost totally up, at which point they just drop sharply. On the complete opposite end of the spectrum is the Conceder function. An agent using this strategy yields and gives up value almost immediately, dropping their price rapidly right at the beginning of the negotiation.

10. Task-Oriented Domains (TODs)

Negotiation in domains where agents divide up tasks (not just resources).

Motivating Example

The Carpool Problem

You have 3 children at different schools. Your neighbour has 4 children. Delivery of each child is an indivisible task. You can negotiate a carpool — carry each other's children to shared destinations. The worst case is no agreement: you just do your own tasks, no worse off than before.

TOD Formal Definition

A task-oriented domain is a triple ⟨T, Ag, c⟩:

  • T — the (finite) set of all possible tasks
  • Ag = {1, ..., n} — the (finite) set of participant agents
  • c : 2T → ℝ+ — the cost function for executing each subset of tasks

Cost Function Properties

  • Monotonic: if T1 ⊆ T2, then c(T1) ≤ c(T2) — more tasks cost more
  • c(∅) = 0 — doing nothing costs nothing

An encounter is a collection of tasks ⟨T1, ..., Tn⟩ where Ti ⊆ T for each agent. This is where agents can negotiate by reallocating tasks.

11. Deals in TODs

With two agents and encounter ⟨T1, T2⟩, a deal δ = ⟨D1, D2⟩ is an allocation of the tasks T1 ∪ T2.

Cost of Deal δ to Agent i
costi(δ) = c(Di)
Utility of Deal δ to Agent i
utilityi(δ) = c(Ti) − costi(δ)

Key Concepts

  • Utility = how much the agent gains from the deal (original cost minus new cost)
  • If utility is negative, the agent is worse off
  • A deal is individually rational if it gives positive utility
  • The conflict deal Θ = ⟨T1, T2⟩ (original allocation) → utilityi(Θ) = 0 for all agents

12. Dominance & the Negotiation Set

A deal δ1 dominates another deal δ2 (i.e., δ1 ≻ δ2) if and only if:

Dominance Conditions

  • δ1 is at least as good for every agent: ∀i, utilityi(δ1) ≥ utilityi(δ2)
  • δ1 is strictly better for some agent: ∃i, utilityi(δ1) > utilityi(δ2)

Key Definitions

  • Pareto optimal: a deal that is not dominated by any other deal
  • Individually rational: a deal that weakly dominates the conflict deal (at least as good as no deal for everyone)

The Negotiation Set

The negotiation set consists of deals that are both individually rational AND Pareto optimal. These are the only "reasonable" deals — agents won't accept worse-than-conflict deals, and non-Pareto deals can always be improved.

13. The Monotonic Concession Protocol

A one-to-one negotiation protocol where agents propose simultaneously.

Protocol Rules

1
Round 0: Both agents simultaneously propose a deal from the negotiation set.
2
Agreement check: If one agent finds the other's proposal at least as good as their own → deal! (If both hold, flip a coin.)
3
Round u+1: Each agent either concedes (makes a better offer for the opponent) or waits.
4
Monotonic rule: No agent can make a proposal that is less preferred by the other than their previous offer. No backtracking!
5
Termination: If neither agent concedes in some round u > 0 → conflict deal.

Properties

  • Guaranteed to end in a finite number of rounds (if deal set is finite)
  • Easy to verify if rules are being followed
  • No guarantee of speed — number of possible deals is O(2|T|), exponential in the number of tasks

Utility functions of both agents are assumed to be known to both agents.

Show Transcript — Monotonic Concession
Instead of taking turns like we saw in Rubinstein's model, agents propose deals simultaneously right in round one. The absolute core rule here, the monotonic part, is that no agent is ever allowed to backtrack. You literally cannot make a proposal that the other agent prefers less than your previous offer. And crucially, if you hit a round where neither agent makes a concession, the negotiation instantly terminates in that dreaded conflict deal.

14. Negotiation Strategies

Three key questions when using the monotonic concession protocol:

QuestionAnswer
What should an agent's first proposal be? Its most preferred deal
On any given round, who should concede? The agent least willing to risk conflict
If an agent concedes, how much? Just enough to change the balance of risk

The Zeuthen strategy answers the last two questions mathematically.

15. The Zeuthen Strategy

Key idea: evaluate an agent's willingness to risk conflict.

Core Intuition

  • If you've conceded a lot, your proposal is near the conflict deal
  • In case conflict occurs, you're not much worse off
  • So you are more willing to risk conflict (hold firm)

An agent is more willing to risk conflict when the difference between its current proposal and the conflict deal is low.

Show Transcript — Zeuthen Strategy
The Zeuthen Strategy dictates that an agent continuously measures its willingness to risk conflict. Intuitively, an agent is way more willing to risk a conflict if the utility difference between their current proposal and the dreaded conflict deal is very low. They simply have less to lose. Under this strategy, an agent will concede, if and literally only if, its calculated willingness to risk conflict is smaller than or equal to the other agent's risk.

16. Zeuthen Risk Formula

Agent i's willingness to risk conflict at round t, denoted riskit:

Zeuthen Risk Formula
riskit = { 1   if utilityi(δit) = 0   |   [utilityi(δit) − utilityi(δjt)] / utilityi(δit)   otherwise }

Where δit is agent i's proposal at round t, and δjt is the other agent's proposal.

Zeuthen Decision Rules

  • The agent with the smaller risk value should concede (less willing to risk conflict → more to lose)
  • Concede just enough to make the other agent's risk value less than your own
  • Start by proposing your most preferred deal

17. Properties of the Zeuthen Strategy

When Both Agents Use Zeuthen + Monotonic Concession

  • Guaranteed to terminate
  • No guarantee the negotiation will succeed
  • If agreement is reached, it is guaranteed to be individually rational AND Pareto optimal

Nash Equilibrium

The Zeuthen strategy is in Nash equilibrium: if one agent uses it, the other can do no better than using it too. This is valuable for designing automated agents — the strategy can be publicly known and no one can exploit it.

The Equal-Risk Edge Case

If both agents have equal willingness to risk conflict on the final round, the strategy says both should concede. But an intelligent agent might defect (hold firm), hoping the other concedes. If both defect → conflict deal (everyone loses). Solution: flip a coin to decide who concedes.

18. Deception in TODs

Deception can benefit agents in two ways:

Phantom & Decoy Tasks

  • Pretending you have tasks that you don't
  • Can be prevented by ensuring tasks are verifiable

Hidden Tasks

  • Pretending not to have tasks that you do
  • If you hide a task similar to another agent's, they won't propose taking it on
  • May incur a small additional cost to you, but avoids a beneficial swap
