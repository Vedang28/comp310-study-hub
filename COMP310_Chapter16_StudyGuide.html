1. Introduction

Argumentation is a means through which agents can reach agreement. Unlike the negotiation mechanisms of Chapter 15, argumentation allows for more complex interactions — agents can present reasons, challenge foundations, and build structured logical positions.

Argumentation can be used for a range of tasks including negotiation, inquiry, persuasion, and deliberation.

2. Why Argumentation?

In multi-agent systems, agents don't always agree. They need a systematic way to resolve conflicts. Rather than just exchanging offers (as in negotiation), argumentation lets agents present structured reasons for their positions and challenge each other's reasoning.

Key distinction from negotiation: In negotiation, agents exchange proposals and make concessions. In argumentation, agents present arguments backed by evidence and logic, and these arguments can be attacked and defended.

3. Types of Argument

Michael Gilbert identified four modes of argument:

ModeDescriptionKey Feature
LogicalBased on formal logic, premises, and conclusionsRational deduction
EmotionalAppeals to feelings and emotionsAffective persuasion
VisceralPhysical or instinctive responsesBody language, tone
KisceralBased on intuition, faith, or mysticismInner conviction

In multi-agent systems, we focus primarily on the logical mode — arguments that can be formalized mathematically. This gives us two main frameworks: abstract argumentation (Dung) and deductive argumentation (Toulmin-style).

4. Abstract Argumentation (Dung)

Dung's abstract argumentation framework treats arguments as atomic, indivisible entities. We don't look inside arguments at their internal structure — we only care about the attack relationships between them.

An argumentation framework is a pair: <Args, Attacks>
where Args = set of arguments, Attacks ⊆ Args × Args
Example

Consider arguments {A, B, C} where A attacks B and B attacks C.

Args = {A, B, C}
Attacks = {(A,B), (B,C)}

This is represented as a directed graph: A → B → C

5. Attack Relations

In an argumentation graph, an arrow from A to B means "A attacks B".

Rebuttal

A direct contradiction — two arguments with opposing conclusions. Like two people yelling "it is!" and "it is not!" at each other.

Symmetrical — if A rebuts B, then B rebuts A.

Undercut

Attacks the foundation/support of an argument, not the conclusion itself. Like knocking the legs out from under a table.

Asymmetrical — A can undercut B without B undercutting A.

Everyday Example

P: "Since the weather is sunny, I'll go cycling" Support → Conclusion

Q: "Since today is a weekday and I have work, I can't go cycling" Rebuts P

R: "Since today is a holiday, I don't have to go to work" Undercuts Q

R doesn't directly say "I can go cycling" — it attacks Q's support (the premise about having to work).

Show Transcript — Rebuttals & Undercuts
So, first up is a rebuttal. The crucial point here is that a rebuttal is a direct contradiction. It's literally like two people yelling "it is" and "it is not" at each other. If argument 1 says a premise is true and argument 2 says that exact same premise is false, boom, that's a rebuttal. A total head-on collision of facts. Now, an undercut. An undercut is much sneakier. It attacks the very foundation, the supporting evidence, of the other person's argument. You aren't necessarily saying their final conclusion is totally wrong, but you are proving that the reason they arrived at that conclusion, yeah, it's flawed. It's like knocking the legs out from under a table.

6. Conflict-Free Positions

A position is a subset of arguments. A position is conflict-free if no argument in the set attacks another argument in the same set.

A set S ⊆ Args is conflict-free iff
∄ A, B ∈ S such that (A, B) ∈ Attacks
Example: Graph A → B → C

Conflict-free sets: ∅, {A}, {B}, {C}, {A,C}

{A,B} is not conflict-free because A attacks B.

{B,C} is not conflict-free because B attacks C.

Problem: Conflict-free gives us too many options. The empty set ∅ is always conflict-free (trivially — nothing to attack). We need stricter definitions to determine which arguments actually "win" the debate.

Show Transcript — Conflict-Free
Now, if we only look for conflict-free sets, we end up with a massive kind of chaotic list of possibilities. A conflict-free set simply means no argument inside the set attacks another argument in that same set. But notice the very first one listed, the empty set. Well, technically, a set with nothing in it has no conflicts. But as you can easily see, just being conflict-free gives us way too many options. It doesn't actually tell us who won the debate, which is exactly why we need stricter definitions.

7. Mutually Defensive Positions

A position is mutually defensive if for every argument in the set that is attacked by an outside argument, there exists another argument in the set that counter-attacks (defends against) that attacker.

A set S is mutually defensive iff
∀ B ∉ S: if (B, A) ∈ Attacks for some A ∈ S,
then ∃ C ∈ S such that (C, B) ∈ Attacks

Note: The empty set ∅ is trivially mutually defensive (nothing to defend). But a set that is mutually defensive is not necessarily conflict-free — the two properties are independent.

8. Admissible Positions

A position is admissible if it is both conflict-free AND mutually defensive. This is the sweet spot — your set doesn't fight itself, and it can defend against all outside attacks.

Admissible = Conflict-Free + Mutually Defensive
  • Check that no argument in the set attacks another argument in the same set (conflict-free)
  • For every external attack on any member of the set, verify a counter-attack exists within the set (mutually defensive)
  • If both conditions hold, the set is admissible

The empty set ∅ is always admissible — trivially conflict-free and trivially mutually defensive.

Show Transcript — Admissibility
So to be admissible, your position must make sense internally and be capable of defending itself. It has to be a completely coherent stance. If an outside argument attacks you, your set absolutely must contain a counterargument that attacks the attacker. It's mutually defensive. If you can't defend against an incoming attack, your set is not admissible. Simple as that. Now, the empty set is always admissible because, well, there's nothing there to attack, but obviously we're looking for more substantial positions.

9. Preferred Extensions

A preferred extension is a maximal admissible set — an admissible set that cannot be made any larger while remaining admissible. You've pushed your defendable territory to the absolute limit.

S is a preferred extension iff
S is admissible AND ∄ S' ⊃ S such that S' is also admissible

Guarantee: Every argumentation framework has at least one preferred extension (at minimum, the empty set is admissible, so there's always at least one maximal admissible set).

Finding Preferred Extensions — Process
  1. List all conflict-free sets
  2. Filter to only those that are also mutually defensive (= admissible sets)
  3. Remove any admissible set that is a proper subset of another admissible set
  4. The remaining sets are the preferred extensions
Show Transcript — Preferred Extensions
And that's where a preferred extension comes in. It takes admissibility a step further into a maximal, admissible set. This means it's a fully expanded position that will break if you try to add even one more argument to it. You are pushing your defendable territory to the absolute limit. You basically gather as many arguments as you possibly can that still perfectly defend each other. But the moment you pull in an argument that introduces an undefended attack, you've gone too far. And remember, every argumentation graph is guaranteed to have at least one preferred extension.

10. Pathological Cases

Mutual Attacks

When two arguments attack each other (A ↔ B), both {A} and {B} are admissible (each defends itself against the other). This gives us two preferred extensions: {A} and {B}.

Odd-Length Cycles

An odd cycle like A → B → C → A creates a problem. No non-empty conflict-free set can be mutually defensive. The only preferred extension is ∅ — the empty set.

Self-Attacking Arguments

If an argument attacks itself (A → A), it can never be in any admissible set because including it immediately violates the conflict-free condition.

Larger Graphs

Complex Graph Example

Consider: A → B → C, D → C, D → E, E → D

Finding preferred extensions requires systematic checking of all conflict-free sets for admissibility, then finding the maximal ones.

Multiple preferred extensions can coexist, representing different "defensible worldviews."

11. Credulous & Sceptical Acceptance

Given the preferred extensions, we can classify arguments by how strongly they're accepted:

Credulously Accepted

An argument is credulously accepted if it appears in at least one preferred extension.

Optimistic — "there exists a defensible worldview that includes this argument."

Sceptically Accepted

An argument is sceptically accepted if it appears in every preferred extension.

Cautious — "no matter which defensible worldview you adopt, this argument is included."

Key insight: If there is only one preferred extension, then credulously accepted = sceptically accepted (same set of arguments).

Example: A ↔ B (mutual attack)

Preferred extensions: {A} and {B}

A is credulously accepted (in {A}) but not sceptically accepted (not in {B})

B is credulously accepted (in {B}) but not sceptically accepted (not in {A})

No argument is sceptically accepted here.

12. Grounded Extensions

The grounded extension is the most sceptical (cautious) approach. It contains only arguments that are absolutely guaranteed to be acceptable. Unlike preferred extensions (which can be multiple), there is always exactly one grounded extension.

Preferred Extension

Pushes for the largest defendable position — "build a sprawling castle."

Can have multiple preferred extensions.

Brave / Expansive

Grounded Extension

Plays it incredibly safe — "an immovable anchor built from absolute guarantees."

Always exactly one grounded extension.

Cautious / Sceptical

In multi-agent systems: The choice between preferred and grounded extensions dictates how an AI behaves. Does it take a strong, expansive stance that might be debated? Or does it only commit to undeniable bedrock facts?

13. The IN/OUT Algorithm

Computing the grounded extension uses a simple iterative labelling algorithm:

  • Find unattacked arguments — any argument with no incoming attacks is labelled IN
  • Mark attacked arguments OUT — any argument attacked by an IN argument is labelled OUT
  • Re-check the graph — did removing OUT arguments free up new unattacked arguments? If so, label them IN
  • Repeat until no more changes occur — the set of all IN arguments is the grounded extension

Arguments left unlabelled (neither IN nor OUT) are undecided — we cannot determine their status. This happens with cycles (mutual attacks, odd cycles, etc.).

Grounded Extension = { all arguments labelled IN }
Show Transcript — Grounded Algorithm
Let's follow a strict algorithm to build one. It's a very systematic iterative process. First, look at your graph. Is there any argument that nobody is attacking? Great. Keep them in. Now, because those arguments are in, anything they attack is instantly destroyed. Throw them out. Delete them completely. Now look at the graph again. Did deleting those arguments suddenly free up a new argument from being attacked? If yes, that new argument is now in. You just repeat this cycle until the dust settles and nothing else changes.

16. Deductive Argumentation

Abstract argumentation treats arguments as atomic (no internal structure). But arguments do have structure — premises, warrants, conclusions — that can be exploited.

In deductive argumentation, arguments are modelled using logical formulae. This models defeasible reasoning — reasoning that can be overturned by new evidence.

17. Toulmin's Argument Model

Stephen Toulmin proposed a structured model of argument with six components:

ComponentRoleDescription
Claim (C)ConclusionThe conclusion whose merit must be established
Ground/Support (S)Fact/EvidenceA fact appealed to as foundation for the claim
Warrant (W)Rule/AxiomA statement authorising movement from ground to claim
Backing (B)CredentialsCertifies the warrant; introduced when warrant alone isn't convincing
Rebuttal (R)ExceptionRestrictions that may legitimately be applied to the claim
Qualifier (Q)Degree of forceWords expressing certainty: "probably", "certainly", "impossible"
(S) Support ──────→ Therefore (Q) Qualifier + (C) Claim
      │                                      │
  Since  Because                       Unless
  (W)    (B)                           (R)
Warrant  Backing                      Rebuttal
Harry's Nationality (Toulmin's Example)

Support: Harry was born in Bermuda

Warrant: A man born in Bermuda will generally be a British subject

Backing: The following statutes and other legal provisions...

18. Formal Deductive Arguments

Given a database Σ (a possibly inconsistent set of logical formulae representing available evidence), a deductive argument is a pair (S, p) where:

A deductive argument (S, p) requires:

1. S ⊆ Σ   (based on available evidence)
2. S ⊢ p   (conclusion provable from support)
3. S is logically consistent
4. There is no S' ⊂ S such that S' ⊢ p   (minimal support)
Socrates Example

Database Σ = { human(Socrates), human(Heracles), father(Heracles, Zeus), father(Apollo, Zeus), divine(X) → ¬mortal(X), human(X) → mortal(X), father(X, Zeus) → divine(X), ¬(father(X, Zeus)) → divine(X) }

Arg₁ = ({human(Socrates), human(X) → mortal(X)}, mortal(Socrates))

S = {human(Socrates), human(X) → mortal(X)}, p = mortal(Socrates)

This is valid: S ⊆ Σ, S ⊢ p, S is consistent, and no proper subset of S proves p.

19. Rebut vs Undercut (Formal Definition)

Let (S₁, p₁) and (S₂, p₂) be arguments from database Σ.

Rebut

(S₂, p₂) rebuts (S₁, p₁) if:

p₂ ≡ ¬p₁

The conclusions directly contradict each other.

Always symmetrical — if A rebuts B, then B rebuts A.

Undercut

(S₂, p₂) undercuts (S₁, p₁) if:

p₂ ≡ ¬q₁ for some q₁ ∈ S₁

The conclusion of one argument attacks a premise in the support of the other.

Not necessarily symmetrical

20. Deductive Argumentation — Examples

Heracles Example

Rebut and Undercut in Action

Arg₂ = ({human(Heracles), human(X) → mortal(X)}, mortal(Heracles))

Arg₃ = ({father(Heracles, Zeus), father(X,Zeus) → divine(X), divine(X) → ¬mortal(X)}, ¬mortal(Heracles))

Arg₃ rebuts Arg₂: mortal(Heracles) vs ¬mortal(Heracles) — direct contradiction.


Arg₄ = ({¬(father(X,Zeus) → divine(X))}, ¬(father(X,Zeus) → divine(X)))

Arg₄ undercuts Arg₃: Arg₄'s conclusion negates a premise in Arg₃'s support set.

Recycling Example

Three Arguments about Recycling

Argument x: a = "We recycle", b = "We save resources", a → b = "If we recycle, then we save resources"

Formally: ({a, a → b}, b)


Argument y: c = "Recycled products are not used", a ∧ c → ¬b = "If we recycle and recycled products are not used then we don't save resources"

Formally: ({a, c, a ∧ c → ¬b}, ¬b)

x and y rebut each other (b vs ¬b)


Argument z: d = "We create more desirable recycled products", d → ¬c = "If we create more desirable recycled products then recycled products are used"

Formally: ({d, d → ¬c}, ¬c)

z undercuts y (¬c attacks premise c in y's support)

21. Attack and Defeat

Deductive argumentation connects back to Dung's abstract framework:

  • A rebuttal or undercut between two deductive arguments becomes an attack in the Dung-style system
  • Once attacks are identified, we can use preferred extensions or grounded extensions to determine which arguments to accept

Important note: A rebut is symmetrical — this causes problems with some kinds of extensions (e.g., it creates mutual attacks, which can lead to multiple preferred extensions or empty grounded extensions).

22. Expected Utility

Pivoting from logical debate to decision theory. When an agent takes action in an uncertain world, we need hard numbers to measure risk and reward.

An agent's environment is described by:

  • States (E) — the possible states of the environment
  • Actions (α) — actions the agent can take
  • Transition probabilities — P(state' | action, state)
  • Utility function U — the payoff for each outcome
Expected Utility = Σ [P(run) × U(run)]

where P(run) = product of transition probabilities along the path
and U(run) = sum of utilities earned along the path

A run is a complete end-to-end path through the agent's decision tree — from the initial state to a terminal state. Each run has a probability (product of transition probabilities) and a utility (sum of payoffs).

Show Transcript — Expected Utility

We have actions, labeled alpha. We have the probability of an action leading to a specific state. And finally, a utility function, those U values, which represent the points or payoff the agent gets for that outcome.

23. Finding the Optimal Agent

To determine which agent is optimal, calculate the expected utility for each agent and compare. The agent with the higher expected utility is the optimal agent for that environment.

  • Draw the decision tree — visualise all possible runs for each agent, branching at each action
  • Identify all runs — trace every complete path from start state to end state
  • Calculate P(run) — multiply all transition probabilities along each path
  • Calculate U(run) — sum all utilities earned along each path
  • Compute Expected Utility — EU = Σ P(run) × U(run) for all runs
  • Compare agents — the agent with higher EU is optimal
Exam Example — Comparing Two Agents

Agent 1: Starting at E₀, action α₀ branches to E₁ or E₂. From there, action α₂ leads to final states.

Agent 2: Different action choices leading to different paths and probabilities.


After computing all runs:
